📝 Descripción

El Buen Sabor es un restaurante de comida criolla y fusión peruana ubicado en el distrito de San Miguel, Lima. Ofrece una carta variada que incluye entradas, platos de fondo, bebidas y postres elaborados con ingredientes frescos y de alta calidad. Cuenta con un salón principal, una terraza y un área de bar.

🎯 Misión

Brindar una experiencia gastronómica excepcional a nuestros clientes, ofreciendo platos de alta calidad con sabor peruano en un ambiente acogedor y con un servicio eficiente.

🔭 Visión

Ser reconocido como uno de los mejores restaurantes de comida peruana en Lima, destacando por la innovación en nuestra carta, la calidad del servicio y la implementación de tecnología en nuestros procesos operativos.

Realidad Problemática

🔍 Diagnóstico Situacional

El restaurante "El Buen Sabor" actualmente gestiona la totalidad de sus operaciones de manera manual y basada en papel, lo cual genera múltiples problemas operativos que impactan directamente en la calidad del servicio, la eficiencia del personal y la rentabilidad del negocio.

N°ProblemaImpactoFrecuencia
1Toma de pedidos en papel — Errores de lectura, pedidos incorrectos, pérdida de comandasPlatos equivocados. Pérdidas por devolucionesDiario
2Sin control de mesas — Meseros dependen de su memoria para saber disponibilidadEsperas innecesarias. Pérdida de clientesDiario
3Comunicación deficiente cocina-salón — Aviso con campana o gritosPlatos se enfrían. Clientes insatisfechos8-10 veces/día
4Facturación manual — Cálculos con calculadora, boletas a manoColas, errores de cobro, sin reportesDiario
5Sin reportes ni métricas — No se sabe qué platos se venden másDecisiones por intuición, no por datosPermanente
6Control de inventario deficiente — Verificación visual, cuadernos desactualizadosInsumos agotados sin aviso, desperdicio2-3 veces/sem

Descripción de la Solución

💡 Propuesta

Desarrollo e implementación de un Sistema Web de Gestión de Restaurante que digitalice y automatice los procesos operativos principales, reemplazando los métodos manuales por una plataforma integrada, accesible desde cualquier dispositivo con navegador web.

🔐

Módulo de Autenticación

Login seguro con JWT. Roles: Admin, Mesero, Cocinero, Cajero.

Resuelve: Falta de control de acceso

🍽️

Módulo de Menú

CRUD digital de categorías y platos con precios, imágenes y disponibilidad en tiempo real.

Resuelve: Carta desactualizada en papel

📋

Módulo de Pedidos

Toma de pedidos digital desde tablet, envío instantáneo a cocina, seguimiento de estados.

Resuelve: Pedidos en papel con errores

🪑

Módulo de Mesas

Mapa visual interactivo con estados en tiempo real (Disponible, Ocupada, Reservada).

Resuelve: Control de mesas por memoria

👨‍🍳

Módulo de Cocina

Pantalla con pedidos en cola, notificaciones automáticas cuando el plato está listo.

Resuelve: Comunicación deficiente

💰

Módulo de Facturación

Generación automática de cuentas, cálculo instantáneo de totales.

Resuelve: Cálculos manuales y lentos

📊

Módulo de Reportes

Dashboard con ventas diarias, platos populares, gráficos interactivos.

Resuelve: Sin métricas del negocio

👥

Módulo de Usuarios

Gestión de empleados, roles y permisos del sistema.

Resuelve: Sin control de personal

-- ============================================
-- BASE DE DATOS: SISTEMA DE GESTIÓN DE RESTAURANTE
-- Motor: MySQL 8  |  Fecha: Septiembre 2026
-- ============================================

CREATE DATABASE IF NOT EXISTS restaurante_db
CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

USE restaurante_db;

-- TABLA: usuario
CREATE TABLE usuario (
    id            BIGINT AUTO_INCREMENT PRIMARY KEY,
    nombre        VARCHAR(100)    NOT NULL,
    apellido      VARCHAR(100)    NOT NULL,
    email         VARCHAR(150)    NOT NULL UNIQUE,
    password      VARCHAR(255)    NOT NULL,
    rol           ENUM('ADMIN','MESERO','COCINERO','CAJERO') NOT NULL DEFAULT 'MESERO',
    activo        BOOLEAN         NOT NULL DEFAULT TRUE,
    created_at    DATETIME        DEFAULT CURRENT_TIMESTAMP,
    updated_at    DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB;

-- TABLA: categoria
CREATE TABLE categoria (
    id            BIGINT AUTO_INCREMENT PRIMARY KEY,
    nombre        VARCHAR(100)    NOT NULL UNIQUE,
    descripcion   VARCHAR(255)    NULL,
    activa        BOOLEAN         NOT NULL DEFAULT TRUE,
    created_at    DATETIME        DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;

-- TABLA: plato
CREATE TABLE plato (
    id            BIGINT AUTO_INCREMENT PRIMARY KEY,
    nombre        VARCHAR(150)    NOT NULL,
    descripcion   TEXT            NULL,
    precio        DECIMAL(10,2)   NOT NULL CHECK (precio > 0),
    imagen_url    VARCHAR(500)    NULL,
    disponible    BOOLEAN         NOT NULL DEFAULT TRUE,
    categoria_id  BIGINT          NOT NULL,
    created_at    DATETIME        DEFAULT CURRENT_TIMESTAMP,
    updated_at    DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (categoria_id) REFERENCES categoria(id)
) ENGINE=InnoDB;

-- TABLA: mesa
CREATE TABLE mesa (
    id            BIGINT AUTO_INCREMENT PRIMARY KEY,
    numero        INT             NOT NULL UNIQUE,
    capacidad     INT             NOT NULL CHECK (capacidad > 0),
    ubicacion     VARCHAR(100)    NULL,
    estado        ENUM('DISPONIBLE','OCUPADA','RESERVADA') DEFAULT 'DISPONIBLE',
    created_at    DATETIME        DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;

-- TABLA: pedido
CREATE TABLE pedido (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    mesa_id         BIGINT          NOT NULL,
    mesero_id       BIGINT          NOT NULL,
    estado          ENUM('PENDIENTE','EN_PREPARACION','LISTO','ENTREGADO','PAGADO','CANCELADO')
                                    DEFAULT 'PENDIENTE',
    total           DECIMAL(10,2)   DEFAULT 0.00,
    observaciones   TEXT            NULL,
    fecha_creacion  DATETIME        DEFAULT CURRENT_TIMESTAMP,
    fecha_cierre    DATETIME        NULL,
    FOREIGN KEY (mesa_id) REFERENCES mesa(id),
    FOREIGN KEY (mesero_id) REFERENCES usuario(id)
) ENGINE=InnoDB;

-- TABLA: detalle_pedido
CREATE TABLE detalle_pedido (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    pedido_id       BIGINT          NOT NULL,
    plato_id        BIGINT          NOT NULL,
    cantidad        INT             NOT NULL CHECK (cantidad > 0),
    precio_unitario DECIMAL(10,2)   NOT NULL,
    subtotal        DECIMAL(10,2)   NOT NULL,
    notas           VARCHAR(255)    NULL,
    FOREIGN KEY (pedido_id) REFERENCES pedido(id) ON DELETE CASCADE,
    FOREIGN KEY (plato_id) REFERENCES plato(id)
) ENGINE=InnoDB;
